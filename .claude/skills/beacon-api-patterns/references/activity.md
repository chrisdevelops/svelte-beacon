## Purpose

Every meaningful change to a task is recorded in the activity table. This
creates an audit trail visible in the dashboard's Activity tab. It answers
questions like "who changed this task's status?", "when was the AI started?",
and "what was the priority before it was changed?".

Activity logging is not error logging (that's separate) and not AI log
streaming (that uses ai_logs + SSE). Activity logging tracks *human-visible
state changes* to tasks.

---

## What Gets Logged

| Action | Actor | Old Value | New Value | Triggered By |
|--------|-------|-----------|-----------|-------------|
| `task_created` | `system` | — | — | POST /feedback |
| `status_changed` | email or `system` | old status | new status | PATCH /tasks/:id, AI agent |
| `priority_changed` | email | old priority | new priority | PATCH /tasks/:id |
| `type_changed` | email | old type | new type | PATCH /tasks/:id |
| `description_changed` | email | — | — | PATCH /tasks/:id |
| `note_added` | email | — | — | POST /tasks/:id/notes |
| `ai_started` | email | — | task ID | POST /ai/start/:id |
| `ai_stopped` | email | — | — | POST /ai/stop/:id |
| `ai_blocked` | `ai-agent` | — | question text | AI agent output |
| `ai_unblocked` | email | — | answer text | POST /ai/unblock/:id |
| `ai_completed` | `ai-agent` | — | branch name | AI agent output |
| `ai_failed` | `ai-agent` | — | error message | AI agent output |
| `task_deleted` | email | — | — | DELETE /tasks/:id |
| `task_synced` | `system` | — | origin URL | npx beacon pull |

The `actor` field is either an email address (from the auth context), 
`system` (for automated actions like task creation), or `ai-agent` (for 
events generated by the Claude Code agent).

Description changes intentionally omit old/new values to avoid storing
potentially large text diffs in the activity table. The dashboard can
show "description was updated" without the content.

## The Logging Function

```typescript
// src/server/activity.ts

interface LogActivityParams {
  db: Database;
  taskId: string;
  actor: string;      // email, 'system', or 'ai-agent'
  action: string;
  oldValue?: string | null;
  newValue?: string | null;
}

export function logActivity({
  db,
  taskId,
  actor,
  action,
  oldValue = null,
  newValue = null,
}: LogActivityParams): void {
  db.createActivity({
    id: crypto.randomUUID(),
    task_id: taskId,
    actor,
    action,
    old_value: oldValue,
    new_value: newValue,
  });
}
```

The function is synchronous from the caller's perspective (the database
write is fast for a single row insert). It should never throw — if logging
fails, catch and warn rather than failing the parent operation:

```typescript
export function logActivity(params: LogActivityParams): void {
  try {
    params.db.createActivity({
      id: crypto.randomUUID(),
      task_id: params.taskId,
      actor: params.actor,
      action: params.action,
      old_value: params.oldValue ?? null,
      new_value: params.newValue ?? null,
    });
  } catch (err) {
    console.warn('[Beacon] Failed to log activity:', err);
  }
}
```

Activity logging is important but not critical. A failed activity log should
never cause a task update or AI action to fail.

## Integration into Handlers

### Task Creation

```typescript
// Inside POST /feedback handler, after inserting the task
logActivity({
  db,
  taskId: task.id,
  actor: 'system',
  action: 'task_created',
});
```

### Status Change

```typescript
// Inside PATCH /tasks/:id handler
if (body.status && body.status !== existingTask.status) {
  if (!canTransition(existingTask.status, body.status)) {
    return errorResponse(409, `Cannot transition from '${existingTask.status}' to '${body.status}'`);
  }

  logActivity({
    db,
    taskId: params.id,
    actor: auth.email || 'system',
    action: 'status_changed',
    oldValue: existingTask.status,
    newValue: body.status,
  });
}
```

### Multiple Field Updates

When a PATCH updates multiple fields, log each change separately. This
makes the activity feed precise — "status changed from new to backlog"
and "priority changed from medium to critical" as two distinct entries
rather than one vague "task updated" entry:

```typescript
route('PATCH', '/tasks/:id', async (event, db, config, params, auth) => {
  const body = await parseJSON(event);
  const existing = db.getTask(params.id);
  if (!existing) return errorResponse(404, 'Task not found');

  // Validate fields...

  // Log each change before applying
  if (body.status && body.status !== existing.status) {
    logActivity({ db, taskId: params.id, actor: auth.email || 'system',
      action: 'status_changed', oldValue: existing.status, newValue: body.status });
  }

  if (body.priority && body.priority !== existing.priority) {
    logActivity({ db, taskId: params.id, actor: auth.email || 'system',
      action: 'priority_changed', oldValue: existing.priority, newValue: body.priority });
  }

  if (body.type && body.type !== existing.type) {
    logActivity({ db, taskId: params.id, actor: auth.email || 'system',
      action: 'type_changed', oldValue: existing.type, newValue: body.type });
  }

  if (body.description && body.description !== existing.description) {
    logActivity({ db, taskId: params.id, actor: auth.email || 'system',
      action: 'description_changed' });
  }

  // Apply update
  const updated = db.updateTask(params.id, body);
  return jsonResponse(updated);
});
```

### AI Events

AI activity is logged by the AI bridge layer, not by API handlers. When
the agent spawner detects a status marker in Claude Code's output, it
logs the corresponding activity:

```typescript
// In the AI bridge — not in an API handler
function onAgentBlocked(taskId: string, question: string): void {
  db.updateTask(taskId, { status: 'blocked', ai_blocked_reason: question });
  logActivity({
    db, taskId,
    actor: 'ai-agent',
    action: 'ai_blocked',
    newValue: question,
  });
}
```

## Dashboard Display

The activity feed in the dashboard's Activity tab renders each entry as a
human-readable sentence:

| Action | Display |
|--------|---------|
| `task_created` | "Task created" |
| `status_changed` | "Status changed from **backlog** to **ai_working**" |
| `priority_changed` | "Priority changed from **medium** to **critical**" |
| `note_added` | "Admin note added by dev@example.com" |
| `ai_started` | "AI agent started by dev@example.com" |
| `ai_blocked` | "AI agent blocked: *How should I handle...?*" |
| `ai_completed` | "AI agent completed — branch: beacon/fix-14" |

The dashboard formats these on the client side using the action type and
old/new values. The API returns raw activity records and the dashboard
handles presentation.

## Querying Activity

Activity is fetched as part of the task detail response. The query orders
by `created_at DESC` and can optionally be limited:

```typescript
// In the database query layer
function getTaskActivity(taskId: string, limit?: number): ActivityRow[] {
  let sql = `
    SELECT id, task_id, actor, action, old_value, new_value, created_at
    FROM activity
    WHERE task_id = ?
    ORDER BY created_at DESC
  `;
  if (limit) sql += ` LIMIT ${limit}`;
  return db.execute(sql, [taskId]).rows;
}
```

The task detail endpoint includes the most recent 50 activity entries by
default. The dashboard can request more if the user scrolls.
